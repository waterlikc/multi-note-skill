Spring Boot 3 订单接口：从 Controller 到 SQL

一次请求穿过三层：Controller 收参数、Service 管事务、Mapper 绑 SQL；异常在边界统一收口。

分层：一次请求经过谁Controller：只接参数、只返结果DTO 校验：把坏请求挡在门外Service：事务边界画在哪Mapper：SQL 与参数绑定排错顺序：日志 → 参数 → SQL自测：三个必答

来源材料

06排错顺序：日志 → 参数 → SQL

  • 先看异常栈第一行，确认是 4xx 还是 5xx。
  • 400 先核对请求体字段名与类型。
  • 5xx 打开 SQL 日志，确认语句与参数。
  • 用最小请求复现，再逐层加回条件。
提示

不要在 Controller 里 try-catch 吞掉异常；统一异常处理只做转换，不隐藏堆栈。

依据：[S1]

补充解释

07自测：三个必答

1. @Transactional 默认对哪些异常回滚？

答：RuntimeException 及其子类；受检异常需要 rollbackFor = Exception.class。

2. #{} 和 ${} 的区别？

答：#{} 走 PreparedStatement 占位符并处理参数；${} 直接拼接字符串，可能被注入。

3. 接口返回 400 和 500，分别先查什么？

答：400 查参数绑定与校验；500 查服务端异常栈与 SQL。
