# 笔记技能：业务痛点与功能映射

> 用途：说明设计取舍时先讲“为什么”，再讲“做了什么”。不是功能清单。

## 一、人为什么记笔记

1. **外部记忆**：课堂/会议/视频信息密度高，当场记不全，需要留一个可回看的版本。
2. **理解结构**：把散乱材料压成“概念—例子—易错点”，才能复述和应用。
3. **检索凭证**：写报告、做项目、汇报时要能找回原话、数据、出处。
4. **行动转化**：会议要落到负责人和截止时间；学习要落到自测和复习。

记笔记的终点不是“保存”，是**以后找得到、看得懂、用得上**。

## 二、现在的六个断点

| 断点 | 学生/老师的真实场景 | 现有做法的问题 |
|---|---|---|
| 记不完 | 视频 12 分钟，边看边暂停 | 只记零散截图，没有结构 |
| 找不到 | 一学期几十份笔记，只记得“好像在哪” | 文件夹+文件名，搜不到正文 |
| 对不上 | 引用一句话，不知道是原话还是自己概括 | AI 总结混在一起，无法核验 |
| 打不开 | 换电脑/断网/打印，样式全乱 | 依赖在线工具或外部 CSS |
| 不复看 | 记完就结束，考前从头翻 | 没有复习节奏与自测 |
| 不会用 | 笔记是“抄”，不是“练” | 缺少迁移任务，换题就不会 |

## 三、我们怎么解（功能 ↔ 痛点）

| 痛点 | 功能 | 证据 |
|---|---|---|
| 多模态记不完 | 文字/图片/字幕统一进契约；图片内联 data URI；视频字幕切时间戳 | 105 项测试；自录视频 9 节笔记 |
| 找不到 | 笔记关键词 + 课程包关键词索引，点词直达章节 | 12 份笔记 / 104 节 / 31 个关键词 / 0 审计问题 |
| 对不上 | S 编号来源、source/supplement/uncertain 三分、audit 校验 | audit 0 问题；无外链/失效锚点 |
| 打不开 | 单文件内联 CSS/SVG，无脚本无外链，A4 打印 | 三种主题打印验证 |
| 不复看 | 目标/自测/状态随文件走，1/3/7/16 复习 | 状态校验：模拟作答不计掌握 |
| 不会用 | 每份笔记 3 个以上迁移任务，三级自评 | 规范检查强制“迁移章节” |
| 笔记多了 | 课程包 pack：一次渲染多份 + 索引 + 关键词页 | 一条命令，104 节，0 问题 |

## 四、不同类笔记怎么处理

同一套契约，不同“场景 + 结构规则”：

- **课堂/课程（course）**：目标 → 概念 → 例题 → 自测 → 迁移；默认杂志排版。
- **技术（tech）**：概念 → 命令/代码 → 排错 → 迁移；默认蓝图排版。
- **读书（reading）**：原文引用 → 作者观点 → 我的反驳 → 迁移；默认手账排版。
- **会议（meeting）**：结论 → 决策表（谁/做什么/截止）→ 风险 → 待办；一页可打印。
- **调研/项目（research/project）**：问题 → 方法 → 证据 → 结论 → 风险。
- **科普（science）**：现象 → 解释 → 常见误解 → 自测。

当前代码已用 scene 区分场景与默认主题；会议必须有决策/行动表、读书必须有原文引用与个人解释，这两条已进入规范检查。其他场景的必填结构仍在第二阶段补。

## 五、竞争性：一句话

> 别人做“生成一篇笔记”，我们做“**可验收、可检索、可复习的课程内容流水线**”。

三个可现场验证的点：

1. 课程包：12 份笔记、104 节、31 个关键词、0 审计问题；含会议与读书样例。
2. 任意关键词 → 命中章节 → 原文锚点；
3. 审计失败演示：删一个来源/改一个锚点，audit 立刻报错。
